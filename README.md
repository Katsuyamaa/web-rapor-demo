# Örnek Gıda A.Ş. — Rapor Sistemi (Portfolio Demo)

This is a **fictional, self-contained portfolio demo** of a warehouse-transfer /
order / cost reporting dashboard originally built for an internal ERP system.
All company names, branch names, product names, and figures in this project
are **synthetic** — generated by a seeded fixture data generator — and do not
represent any real business.

It exists to showcase the frontend (React 19 + Vite + Zustand + ApexCharts +
GridStack drag-and-drop widget dashboards) and a matching serverless API,
deployable on Vercel with **zero external dependencies**: no database, no
scheduler, no real authentication backend.

## Stack

- **Frontend:** React 19, Vite, React Router v6, Zustand, ApexCharts, GridStack
  (`frontend/`)
- **API:** Vercel Node.js Serverless Functions serving deterministic fixture
  data generated in-memory on cold start (`api/`) — no MySQL, no persistence
- **Deploy target:** Vercel (static SPA + serverless functions in one project)

## Demo login


(`admin` / `1234` also works, as an alias.)

## Running locally

```bash
cd frontend
npm install
npm run dev
```

This starts the Vite dev server. To also exercise the `/api/*` serverless
functions locally, install the Vercel CLI and run `vercel dev` from the
project root instead.

## Deploying to Vercel

```bash
npm i -g vercel
vercel link
vercel deploy        # preview
vercel deploy --prod # production
```

`vercel.json` at the repo root builds the SPA (`frontend/`) and wires up the
Node functions in `api/`. No environment variables or database are required.

## Known limitations (by design)

This is a demo, not a production system:

- **No persistence.** POST/PUT/PATCH/DELETE endpoints (widget edits, admin
  CRUD, support tickets, alarm rules, etc.) validate input and return a
  plausible success response, but changes do not survive a page refresh or a
  new serverless cold start — there is no database.
- **No real authentication.** The login flow is a client-side stub; the
  `/api/auth/*` endpoints issue an unsigned demo token, not a real JWT.
- **No real ERP integration.** All data (transfers, orders, cost/inventory
  entries, branches, products) is synthetically generated at server start
  from a seeded random generator — it is internally consistent (totals add
  up, dates are coherent) but entirely fictional.
- Some deeply nested admin workflows are simplified; the priority was making
  every page render correctly with plausible data rather than 1:1 backend
  fidelity.
